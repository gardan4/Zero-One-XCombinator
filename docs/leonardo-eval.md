# Leonardo inference & track eval

Run **finetuned checkpoint → three submission CSVs** on Leonardo (A100). Judges fill in
`.env` credentials; the rest is scripted.

For **training + HF upload** on Leonardo, see branch `leonardo-finetune-reference` and its
`scripts/leonardo_smoke_hf.sh` flow (prestage → SLURM train → upload to `XCombinator/…`).

## Prerequisites

On a **Leonardo login node** (SSH, no 2FA at the hackathon):

```bash
git clone <this-repo> && cd Zero-One-Philyr
cp .env.example .env
```

Fill in at minimum:

| Variable | Purpose |
|----------|---------|
| `ZO_CLUSTER_USER` | Leonardo username |
| `ZO_CLUSTER_ON_LOGIN=1` | You are already on the login node (skip remote ssh/scp) |
| `HF_HOME` | `$SCRATCH/hf` (not `$HOME` — 50 GB limit) |
| `ZO_EXPERIMENTS_DIR` | `$SCRATCH/zo-experiments` |
| `HF_TOKEN` | Download gated/private checkpoints from Hugging Face |
| `ZO_INFER_MODEL` | HF repo id, e.g. `XCombinator/sft-fab-all` |
| `ZO_INFER_MODEL_PATH` | Local path after staging (see below) |
| `ZO_CLUSTER_PROXY` | Proxy password from onboarding deck (compute nodes) |

Pre-stage GPU deps **once** on the login node (compute nodes have no internet):

```bash
just setup          # light uv sync
just judge-setup    # uv sync --extra gpu + local eval inputs
```

## One-command batch eval (in-repo eval set)

Uses `extras/eval_local/` (organizer-format CSVs + `gold.json`, generated by `judge-setup`):

```bash
just judge-stage              # HF weights → $SCRATCH/zo-models/…
just judge-eval --local        # sbatch: predict all 3 tasks + score
just cluster-watch            # wait for SLURM job
```

Results: `experiments/<run_id>/results/`

- `nextstep.csv` — Task 1 (Top-k next step)
- `completion.csv` — Task 2 (sequence completion)
- `anomaly.csv` — Task 3 (valid/invalid + score + rule)

Metrics are logged to the run registry (`just runs`).

Dry-run (render SLURM script, no GPU job):

```bash
just judge-eval --dry-run --local
```

## Manual predict (custom eval CSVs)

Point at any organizer-format inputs; omit `--gold` if you have no labels (outputs only):

```bash
uv run zo-track predict -p hf \
  --model "XCombinator/leonardo-smoke-qwen-0.5b-lora" \
  --valid  /path/to/eval_input_valid.csv \
  --anomaly /path/to/eval_input_anomaly.csv \
  --out    extras/results \
  --tasks  nextstep,completion,anomaly
```

LoRA adapters auto-resolve the base model from `adapter_config.json` (Leonardo scratch paths
are mapped to public HF ids). Override with `ZO_INFER_BASE_MODEL=Qwen/Qwen2.5-0.5B-Instruct`.

**Programmatic API** (same loader used by `-p hf`):

```python
from zo_common.hub_inference import HubInferenceClient

client = HubInferenceClient("XCombinator/leonardo-smoke-qwen-0.5b-lora")
text = client.complete("Your prompt here")
```

Smoke: `uv run python -m zo_common.hub_inference` (needs `HF_TOKEN` + `uv sync --extra gpu`).

Input/output column specs: `packages/eval/zo_eval/submission.py`.

Predictor options: `hf` (batch transformers, default on cluster), `llm` (OpenAI-compatible
vLLM — use `just judge-serve --local` + SSH tunnel), `ngram` / `oracle` (baselines, CPU).

## Optional live demo (vLLM)

Secondary — for a demo video, not required for scoring:

```bash
just judge-serve --local
# SSH tunnel port 8001 to the compute node, then:
export ZO_MODEL_BASE_URL=http://localhost:8001/v1
just track "-p llm --model default --valid extras/eval_local/eval_input_valid.csv ..."
```

## Troubleshooting

| Problem | Fix |
|---------|-----|
| `uv sync --extra gpu --offline` fails on compute node | Run `just judge-setup` on login node first |
| Model not found | Run `just judge-stage`; set `ZO_INFER_MODEL_PATH` in `.env` |
| Missing eval CSVs | Run `just judge-setup`, or pass `--valid` / `--anomaly` manually |
| LoRA checkpoint | Merge adapter to full weights before serve/HF upload (Featherless also needs full weights) |

More cluster detail: [`.claude/knowledge/cluster.md`](../.claude/knowledge/cluster.md).
